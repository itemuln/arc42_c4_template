# arc42 + C4 — Архитектурын баримтжуулалтын загвар

**Software Project Documentation** хичээлийн хүрээнд боловсруулсан, software architecture documentation-ийг Монгол хэлээр бичихэд зориулсан загвар. arc42-ийн бүтэц, C4-ийн дүрслэл, Docs-as-Code аргачлалыг нэгтгэж, архитектурын баримтыг эх файлаас HTML болгон үүсгэж нийтлэх боломжтой.

[HTML баримтыг үзэх](https://itemuln.github.io/idoc/) · [Ашиглах заавар](QUICKSTART.md) · [Лиценз](LICENSE.md)

## Зорилго

Архитектурын баримт нь системийн зорилго, хил, дотоод бүтэц, ажиллагаа, байршуулалт болон чухал шийдвэрүүдийг уншигчид ойлгомжтой хүргэх ёстой. Энэ төсөл дараах зүйлсийг дэмжинэ:

- arc42-ийн 12 хэсэгт юу бичихийг Монгол хэлээр тайлбарлах;
- системийн бүтэц, харилцааг C4 болон sequence/deployment зургаар үзүүлэх;
- чухал сонголтын үндэслэл, үр дагаврыг ADR-аар хадгалах;
- баримтын эх файл, зураг, өөрчлөлтийн түүхийг Git-д хамт удирдах;
- шалгаж, дахин үүсгэж болох HTML баримтыг GitHub Pages-аар хүргэх.

## Хичээлтэй холбогдох нь

Энэхүү repository нь **архитектурын мэдээллийг зохион байгуулах, техникийн баримт бичих, зурагтай тайлбарлах, хувилбар удирдах, нийтлэх** үйл явцыг хэрэгжүүлсэн сургалтын ажил юм.

Хэрэглэгч өөрийн төслийн шаардлага, код, шийдвэр, нотолгоонд тулгуурлан **БӨГЛӨХ** талбаруудыг шинэчилнэ. Жишээ зургууд нь системийн хил, хэсгүүд болон харилцааг хэрхэн дүрслэхийг харуулна. Хэсэг бүрийн дэлгэрэнгүйг төслийн хэрэгцээ, хичээлийн даалгаврын хүрээнд тохируулна.

Баримт боловсруулахдаа санал болгосон шийдэл, хэрэгжүүлсэн зүйл, шалгасан үр дүнг ялгаж тэмдэглэнэ. Ингэснээр архитектурын тайлбар ба түүнийг батлах нотолгоо хоорондоо холбоотой байна.

## C4 ба архитектурын харагдац

arc42 нь архитектурын мэдээллийг зохион байгуулна. C4 нь системийн хил болон бүтцийг тодорхой түвшинд дүрслэхэд тусална.

| Дүрслэл | Баримт дахь байрлал | Тайлбарлах зүйл |
|---|---|---|
| C4 System Context | §3 | Хэрэглэгч, үндсэн систем, хөрш систем |
| C4 Container | §5 | Application болон data store-ийн үүрэг, холбоос |
| Sequence / Runtime | §6 | Нэг scenario-ийн харилцааны дараалал |
| Deployment | §7 | Програмын хэсгүүдийн дэд бүтэц дэх байрлал |

Repository-д эдгээр дөрвөн жишээ зураг, засварлах PlantUML эх болон HTML-д ашиглах SVG хувилбар бий. Шаардлагатай бол C4 Component/Code түвшнийг өөрийн төсөлд нэмж болно. C4 container нь application эсвэл data store-ийг илэрхийлнэ.

## Docs-as-Code ба HTML үүсгэлт

Баримтын үндсэн эх нь [documentation/architecture.adoc](documentation/architecture.adoc). Энэ файл section-уудыг `include`-ээр нэгтгэнэ. Зураг болон ADR нь тусдаа засварлах эхтэй.

**AsciiDoc section-ууд + SVG зураг → Asciidoctor.js → HTML → GitHub Pages**

Эх файлуудыг Git-д хадгалснаар өөрчлөлтийн түүхийг харж, санал/засварыг хамтран хянах боломжтой. `main` дахь өөрчлөлт бүрийн дараа GitHub Actions HTML үүсгэж, section болон дотоод холбоос/зургийг шалгаад нийтэлнэ. Энэ шалгалт нь баримтын бүтэц, үүсгэлтийг батална; баримтжуулж буй системийн runtime ажиллагааг тусад нь шалгана.

## Одоогийн төлөв

Монгол section guidance, бөглөх хүснэгт, ADR загвар, дөрвөн diagram example болон HTML үүсгэлт бэлэн. Анхны GitHub Actions build/deployment амжилттай; нийтэлсэн HTML-ийн Монгол текст, дөрвөн зургийг браузераар шалгасан.

Энэ нь албан бус, товчилсон Монгол adaptation. Монгол хэлний human review хүлээгдэж байна. Өөрийн системийн мэдээллийг бөглөх, түүний runtime/чанарын нотолгоог цуглуулах ажил тухайн төслийн хүрээнд хийгдэнэ.
